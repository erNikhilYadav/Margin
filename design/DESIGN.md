# Margin design: "Paper & Ink"

Warm paper, ink-black text and one vermilion accent, like a well-printed book with an editor's red pen. Light mode leads; dark mode is warm ink, not cold black. Surfaces form a four-step ladder with 1px warm hairlines and no shadows. Vermilion is the only chromatic UI color: it marks focus, the primary action and checked boxes. Danger is a cooler crimson so the primary button never reads as destructive. Status and diff hues are muted print tones (sage, ochre, slate, crimson) so the code carries the color. Titles use a serif; everything else stays Inter at native macOS density (13px body, 28px rows).

Source of truth in code: `src/main/kotlin/ui/theme/Theme.kt`. Fonts: Newsreader (Medium / SemiBold) for display and title, Inter 4.1 (Regular / Medium / SemiBold) and JetBrains Mono 2.304 Regular. App icon: `packaging/Icon.java` (paper tile, vermilion margin rule, ink brush branch with a vermilion head), built into `packaging/Margin.icns`.

## Type (Inter unless noted)
display Newsreader 22/28 Medium -0.2 · title Newsreader 16/20 SemiBold -0.1 · body 13/18 Regular · bodyStrong 13/18 Medium · label 12/16 Medium · caption 11/14 Regular · overline 11/14 SemiBold +0.6, UPPERCASE · mono JetBrains Mono 12/19 · monoSmall 11/19 (hashes, line numbers). No bold above SemiBold, and nothing smaller than 11.

## Space, radius, size
Spacing 2 4 6 8 12 16 24 32. Radius xs 4 (badges) · sm 6 (rows, buttons, inputs) · md 8 (panels) · lg 12 (dialogs, empty-state card) · pill 50%.
Changes column 340 · toolbar 44 (78 traffic-light inset) · branch popup 360 × ≤480 · row 28 · history row 44 · icon button 28 · icon 16 (1.5px stroke) · kind badge 16. Panels sit on canvas with 8px gaps. Inside a panel, separate items with hairlines, never with a second border.

## Motion
FAST 120ms (hover, press, color) · BASE 180ms (selection, expand/collapse, crossfade) · SLOW 260ms (panel/sheet/empty-state enter). Exits run at 0.7x the enter time. Easing: Standard (0.2,0,0,1), enter Decelerate (0.05,0.7,0.1,1), exit Accelerate (0.3,0,1,1). Only color and opacity animate, plus translate of 4px or less. No bounce, no scale on rows. The spinner turns once every 900ms, linear. A first load shows SkeletonBlocks (pressed fill) shaped like the real layout inside a ShimmerHost: one diagonal highlight sweeps every 1.2s with Standard easing, placed by window x so every block on screen shimmers as one, and the content cross-fades in over it (BASE). A reload keeps the content on screen and shows only a 2dp vermilion ProgressStrip at its top, never skeletons again. Buttons and toolbar sync keep their spinners. Rows use the arrow cursor (macOS convention), not the hand.

## Components
- **Layout**: no sidebar. The toolbar spans the window; below it two Panels on canvas with 8px gaps: the changes/history column (340) and the diff/commit pane, which takes the rest. The MRs tab is one full-width Panel.
- **Toolbar** (44, canvas, draggable, 78 left inset for the traffic lights), left to right: repo chip, branch chip, Changes/History/MRs Segmented; then Create MR / View MR, Fetch, Pull, Push on the right. Chips are ToolbarChips (28, radius sm, hover fill, filled while their menu is open). Repo chip: name in title + ChevronDown, max 200; opens a 280 Popover with the recent repos and "Open…  ⌘O". Branch chip: Branch glyph (a Spinner while a checkout runs), name in bodyStrong textSecondary, ChevronDown, max 280, tooltip with the full name and ⌘B; detached HEAD reads "Detached at <hash>". When the window narrows, the branch name truncates first; the repo name truncates only at its own cap. Sync buttons swap their glyph for a Spinner while running; ahead/behind counts live only as Pills on Push (↑n) and Pull (↓n).
- **Popover** (Popups): Panel in surfaceRaised, radius md, borderStrong hairline, soft shadow (12dp, black at 50% dark / 18% light). Opens 4dp under its chip.
- **Branch popup** (⌘B or the branch chip; 360 wide, at most 480 tall): an autofocused InputField "Search branches" over a hairline, then one LazyColumn: "+ New Branch…", then SectionHeaders with counts, "Recent" (the 5 local branches with the newest commit, current excluded), "Local" (all, by name; the current one in bodyStrong with an accentText glyph and a trailing Check) and "Remote" (all, by name, textSecondary; origin/HEAD skipped). Typing filters by case-insensitive substring, hides empty sections and tints the match in accentText SemiBold. The highlight (selection tint, 28 rows) starts on the first branch; Up/Down move it across rows and skip headers, the list scrolls to keep it in view, and the mouse moves it on hover. Enter or click checks out (a remote branch switches to its tracking local), and the popup closes; errors go to the toast. Esc or a click outside closes. "New Branch…" turns into an inline InputField with a caption hint: Enter creates it from the current branch and switches, Esc returns to search.
- **Changes list** (Android Studio style): groups "Changes" (tracked, always shown; "No changes found" in caption tertiary under the title when empty) and "Unversioned" (untracked, only when non-empty). One row per path: Checkbox (checked = staged, dash = partially staged) + KindBadge + file name (body) + directory (caption, tertiary, truncated at the start). Toggles update optimistically. Conflicted rows sort first; checking one marks it resolved. A partially staged file gets an Unstaged/Staged Segmented in the diff header.
  - **Group header band** (shared with the rollback dialog): a full-width, 28 high sticky header on `sectionBand` (#17181B dark / #F7F7F9 light, opaque so rows slide under it) with a hairline below. Contents: tri-state Checkbox (select all/none, conflicts excluded) in the same column as the row checkboxes, the title in overline textSecondary, the count in a quiet pill (caption Medium textTertiary on the hover fill, radius pill), then a 12dp chevron (Down open / Right collapsed, textTertiary, textSecondary on hover). Rows are inset 4 from the panel edge; bands run edge to edge.
  - **Rhythm**: band, 4 air, rows, 4 air, then a full-width hairline before the next band. The first band sits directly under the action bar's hairline, and a band only draws its own bottom hairline, so neither a collapsed group nor a stuck band ever shows a double divider.
  - **Collapse**: click anywhere on the band (outside the checkbox and the hover Rollback icon). Collapsed groups are remembered in Preferences (`changesCollapsedGroups`); ⌘A and ⇧-click ranges skip collapsed rows. Collapsing a stuck band scrolls it back to the top.
- **Changes action bar** (32, hairline below, above the groups): a "Rollback" GhostButton (24 high, Rollback glyph; no count, since a plain click to view a file would otherwise read as a selection; disabled without changes; tooltip "Rollback…  ⌥⌘Z") on the left, a 24dp Refresh TooltipIconButton ("Refresh  ⌘R") on the right.
- **Row selection** (Changes list): separate from the checkboxes. Click selects one row, ⌘-click toggles, ⇧-click selects the range from the last plain/⌘ click. ⌘A selects every row (a row click focuses the list; text fields keep their own ⌘A). Selected rows take a neutral `pressed` fill, never vermilion, because vermilion is the checkbox's "in the commit" color; the row whose diff is shown (the last clicked) is bodyStrong. Clicking never stages. The action bar's Rollback has no count; the dialog pre-checks the selection.
- **Row menu**: right-click a changed file for a Popover at the pointer (220 wide, SidebarItem rows, shortcut in caption tertiary on the right): Show Diff · Rollback… ⌥⌘Z · hairline · Reveal in Finder (not for deleted files). Hovering a row shows a 22dp Rollback icon button at its right end; hovering a group header shows "Rollback all". Rollback acts on the selection when the row is in it, otherwise on that row alone. ⌥⌘Z (Repository menu) rolls back the selection.
- **Modal** (shared by the Create MR sheet and the rollback dialog): scrim black 55% dark / 25% light, centered surfaceRaised Panel at radius lg with a borderStrong hairline, 24 padding, fade + scale from 0.96 (SLOW). Click outside or Esc dismisses.
- **Rollback dialog** (480, Android Studio's Rollback Changes): title "Rollback Changes"; a "Select all" tri-state Checkbox with "N of M selected" in caption; then every changed file in a bordered surface list (at most 10.5 rows, scrolls), grouped under the same sticky group header bands as the Changes list (no chevron, no collapse), each with its own tri-state Checkbox. Rows are FileRows with a Checkbox; clicking the row toggles it. Pre-checked: the files it was opened for (row selection, row menu, row hover icon, "Rollback all", ⌥⌘Z); with none, every tracked file and no untracked one, so a default rollback never trashes new files. Below: the note "Changes to tracked files will be lost. New and untracked files will be moved to the Trash." in body secondary, and, when a checked file is conflicted, a warning box (warning at 10% fill, 35% border, radius sm). Buttons: Cancel (GhostButton, the default: Enter and Esc cancel) and "Rollback N files" (PrimaryButton `danger`, disabled at 0), with a "⌘↵ to roll back" caption on the left. Only a click or ⌘↵ rolls back, and only the checked files. Success shows the toast "Rolled back N files"; new, untracked and rename-target files go to the macOS Trash, never rm.
- **Checkbox**: 14dp box in a 20dp hit target, radius xs. Off: 1px textTertiary edge. On: vermilion fill + onAccent check; indeterminate: vermilion fill + dash. Hover: 3px vermilion ring at 22%.
- **Diff viewer** (surface): mono, used by both the Changes and the History tab. Path header bar of 36px: KindBadge, name, +/- counts, then change navigation (caption counter "7 changes", "2 / 7" once you navigate, tabular figures; ↑ ↓ TooltipIconButtons "Previous change  ⇧F7" / "Next change  F7", disabled at the ends), a glyph Segmented for Unified / Side-by-side, a Segmented for Changes / Whole file (labels collapse to Fold / Unfold glyphs when the header is under 720px), then the Staged/Unstaged control. Both toggles persist in Preferences (`diffSideBySide`, `diffWholeFile`). Whole file reloads with `-U` set to Int.MAX_VALUE (`GitRepo.WHOLE_FILE`), so the file is one hunk; untracked files are always whole.
  - **Unified**: gutter is two 40px line-number columns (monoSmall, diffLineNumber), then the sign, then the text. **Side-by-side**: one LazyColumn of paired rows, so both sides scroll together. Each half has one 40px number column and the sign; a 1px border hairline splits the halves. Within a change block, removed lines fill the left and added lines the right, row by row; the shorter side gets filler with 45° border-colored hairline hatching (three stripes per row, so they run on unbroken). Context shows on both sides; hunk rows span both.
  - Line bg comes from `colors.diffLineBg(type)`, and the gutter of +/- lines uses the gutter tint. Hunk rows: diffHunkBg, diffHunkText, 8px top margin. No wrapping: the gutter stays pinned, and each text column (one in unified, one per side in side-by-side) scrolls horizontally as a whole, with its own scrollbar. Rows are keyed by line numbers, so switching context or layout keeps your place.
  - A change block is a maximal run of +/- lines. F7 / ⇧F7 (menu View > Next / Previous Change; ⌘⇧] / ⌘⇧[ also work) animate the block to about 1/3 from the top, give it a 3px vermilion bar on the left edge, and flash an vermilion tint (14%) that fades in over FAST, holds for 3x SLOW, then fades out with the exit motion. Navigation stays within the file.
- **Commit box** (Panel surfaceRaised, 12px padding): InputField for the summary, an optional multi-line description at minHeight 64, then a row with "Amend" GhostButton and "Commit N files" PrimaryButton. Disable it while the summary is blank; show `loading` while it runs.
- **History**: 44px rows. Line 1 is the subject (body, ellipsized). Line 2 is caption tertiary "hash · author · 2h ago" with the hash in monoSmall. Unpushed commits get a 6px accent dot on the left. Selecting one fills the right pane: header (subject in title, body in secondary, avatar initial + author, relative · absolute date, hash chip that copies the full hash), a "Files" list capped at 6.5 rows, then the selected file's diff. Merges diff against the first parent.
- **Empty state**: centered card at radius lg, max width 360. Repo glyph at 32 in textTertiary, "Open a repository" in display, one caption line, PrimaryButton "Open…" (⌘O), then the recent repos list as SidebarItems. Enter: fade plus 4px rise, SLOW.
- **Errors**: show git's stderr in mono inside a Panel with a danger-tinted border. Never use a modal for a failed fetch.
- **MR list** (MRs tab): a 44 header with "Merge requests", a state Segmented (Open / Merged / Closed / All), a scope Segmented (All / Mine / Assigned / Review requested) and a search InputField (debounced 300ms), then 52px rows. Non-open rows get a state pill. Clicking a row opens the detail in place; a hover icon opens the browser.
- **MR detail**: a 36 top bar ("‹ Merge requests / !iid", browser, refresh). The header has a state pill (Open green, Draft grey, Merged vermilion, Closed danger), the title in display, "!iid · author opened … · updated …", the branch flow, then a FlowRow of caption-label facts: Pipeline (status dot), Approvals, Merge (mergeability), Reviewers, Assignees. Actions sit on the right: Approve / Revoke, "Merge…" (disabled with the reason in a tooltip) and a "⋯" Popover (draft/ready, check out branch, copy branch, browser, Close…, Delete…). Below them an Overview / Changes / Commits Segmented.
  - **Overview**: content capped at 880 and centered. The description is Markdown in a raised Panel, then ACTIVITY: system notes as one quiet caption line with a dot, comments and threads as raised Panels (28 avatar initial, name, @user · time, Markdown body; Reply / Resolve under a hairline). A positioned thread shows its file:line header, which jumps to Changes. A comment box closes the list.
  - **Changes**: a 300 file list (with comment counts) and the shared DiffSection without the whole-file toggle. Threads sit under their line. Hovering a line number tints it vermilion, and a click opens an inline comment box there.
  - **Dialogs** (shared Modal; Enter cancels, never confirms): Merge (squash, delete source branch, merge when pipeline succeeds; sends the head sha so the forge refuses if the branch moved), Close (danger), Delete (danger, enabled only after typing the MR number).
  - Every action is one `glab api` or `gh api` call with a JSON body on stdin (GitHub merges, drafts and threads add a GraphQL call). Afterwards the detail and list reload and a toast confirms; failures show the CLI's message as an error toast. ⌘↵ never commits while the MRs tab is up.
  - **GitHub**: when origin is github.com or a host in gh's hosts.yml, the same screens read pull requests through `gh`: labels say "PRs", "#iid", "Checks", "Enable auto-merge". Revoke approval and Delete are hidden (GitHub has neither). Sign-in is the inline form in this tab, for origin's host; there is no startup sign-in screen.
